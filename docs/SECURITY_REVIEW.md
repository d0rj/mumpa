# Проверка памяти, безопасности и архитектуры — 2026-10-22

Проверен исходный код 1.3.2+40: владение ресурсами при запуске и закрытии,
HTTP-каталоги и метаданные, загрузки, перенос профиля и аудио, браузер каталога,
границы хранения, обновления, Android bridge/manifest и Windows runner.
Исправления находятся в исходниках; установленное приложение и выпуски GitHub
этой работой не обновлялись.

## Исправленные проблемы

| Проблема | Последствие | Изменение |
| --- | --- | --- |
| `Response.fromStream` / `get` собирали весь ответ до проверки размера; `Future.timeout` оставлял исходную операцию работающей | Неограниченный расход памяти и продолжающиеся запросы после таймаута | Общая граница `bounded_http.dart`: лимит во время чтения, общий deadline, `AbortableRequest` / `AbortableMultipartRequest`, отмена подписки, обработка поздних заголовков. Общий HTTP-клиент сохраняется для соседних операций. |
| `SourceOperation.wait` подписывался на долгоживущий cancellation Future для каждого ожидания | Завершённые результаты могли оставаться достижимыми до отмены всей области | Удаляемые обработчики отмены; завершившееся ожидание снимает свой обработчик. Сетевой helper использует ту же схему. |
| Записи аудио через `IOSink.add` не ожидали освобождения буфера | Быстрый источник мог накопить очередь записи размером с передаваемый файл | Ожидаемый `flush` после порции данных в загрузчике, LAN-приёмнике и импорте файла для переназначения. |
| Имя загрузки строилось непосредственно из ID и расширения входной записи | Выход из каталога через разделители, NTFS alternate data streams через `:`, имена устройств Windows | Обычные безопасные ID сохраняют прежние пути для resume; остальные получают хешированное имя. Расширение проходит allowlist аудиоформатов. |
| Завершение создания WebView после `dispose`, повторная инициализация после ошибки без освобождения прежнего экземпляра | Оставшиеся нативные браузерные ресурсы, повторное открытие закрытого транспорта | Идемпотентное закрытие, ожидание создания, проверки после async-границ и очистка частично созданных ресурсов. |
| Кэш `TorrentInfo` сохранял все посещённые раздачи до выхода | Постоянный рост удерживаемых списков файлов | LRU: максимум 32 записи и суммарно 30000 файлов; метаинформация остаётся доступной на диске. |
| Ошибка промежуточного этапа `createApplication` освобождала только замок профиля | Уже созданные декодер, клиенты и подписки оставались без владельца | Очистка приобретённых ресурсов в обратном порядке; передача ответственности контроллеру после успешной композиции. Ошибка одной очистки не останавливает остальные. |
| Поздний сетевой текст песни перезаписывал импортированный пользователем LRC; закрытый LyricsRepository мог выполнять очередь запросов | Потеря пользовательского текста, лишняя фоновая работа | Ревизия пользовательской правки, последовательная запись и отмена области жизни репозитория. |
| Android MethodChannel сохранял обработчик закрытого AppController | Глобальный канал удерживал контроллер приложения | Снятие обработчика в `dispose`. |

Чтение HTTP-данных ограничено отдельно от дисковой квоты: обычно 4 МиБ для
каталогов/метаданных, 2 МиБ для RuTor, 1 МиБ для текстов и ответа загрузки
метаданных в TorrServer, 16 МиБ для torrent-метаданных и 4 КиБ для echo.
Переходы и ненужные тела ответов Torrage/Jackett отменяются вместо неограниченного
дочитывания. Уже существующие ограничения artwork и updater сохранены.

## Проверки и воспроизведение

- До изменений: **608 passed, 7 skipped**, анализатор без замечаний.
- После изменений: **617 passed, 7 skipped**, анализатор без замечаний.
- Четыре новых теста запускались с соответствующими исходными файлами из HEAD:
  поток каталога, гонка LRC, позднее создание WebView и неограниченный кэш.
  Все четыре воспроизвели ошибку до исправления; исправленные файлы восстановлены
  в `finally`. Они проходят на итоговом коде.
- Дополнительные регрессии проверяют остановку oversized/chunked/error responses,
  таймаут тела, поздние заголовки, сохранение общего клиента, завершение при
  widget-pumping, безопасные имена и существующие сценарии pause/resume/Range.
- Настоящий Windows/libmpv: искусственная ошибка инициализации освобождает
  созданный нативный декодер; затем **30** циклов нового приложения, локального
  воспроизведения с продвижением позиции, паузы и повторного shutdown.
  Использованы временная медиатека и оригинальная демозапись. Временный профиль
  удалён в `finally`; production-профиль не участвовал.
- VM service принудительно запускал GC для каждого замера. От цикла 5 до 29:
  Dart heap **128200384 → 128724864 байт** (+0,500 МиБ), RSS
  **489582592 → 506302464 байт** (+15,945 МиБ). Число основных контроллеров и
  репозиториев после GC — по одному текущему экземпляру; `Player` — два
  (включая удерживаемый тестом декодер сбоя). `NativePlayer` вышел на девять
  экземпляров к середине прогона и оставался на этом уровне до конца.
  Это ограниченный debug-прогон с Flutter/test/VM service, а не доказательство
  отсутствия всех утечек или оценка потребления release-версии.

## Зависимости и границы вывода

Для **114 hosted Pub-пакетов** из неизменённого `pubspec.lock` выполнен запрос
к [OSV querybatch](https://google.github.io/osv.dev/post-v1-querybatch/).
Ответ от 2026-10-22: **0 опубликованных advisories для указанных версий**.
Это снимок базы, а не гарантия безопасности пакетов. Обновление всех пакетов
до последних версий не требовалось. Механизм предупреждений Pub описан в
[документации Dart](https://dart.dev/tools/pub/security-advisories).

Текущие отслеживаемые файлы также проверены на характерные форматы приватных
ключей, GitHub-токенов и AWS access key IDs; совпадений нет. Это ограниченный
поиск шаблонов, он не заменяет аудит всей истории и всех форматов секретов.

Проверены существующие границы: portable-профиль отбрасывает пути и credentials;
LAN требует случайный bearer token, ограничивает входные адреса и запрещает
редиректы клиента; updater проверяет размер/SHA-256 перед установкой;
managed HTTP helpers слушают loopback; распаковка runtimes проверяет хеши и пути.
Новых подтверждённых обходов этих границ в просмотренных потоках не найдено.

LAN v1 передаёт данные по HTTP и рассчитан на доверенную локальную сеть:
аутентификация по QR не даёт шифрования от наблюдателя в этой сети. Обновления
доверяют официальному GitHub release origin; SHA-256 не является независимой
цифровой подписью поставщика. Это существующие границы доверия протоколов.

В этой проверке не выполнялись многочасовой soak, профилирование нативной кучи
всех DLL, fuzzing всех декодеров/Chromium, Android heap profiling на физическом
устройстве или независимый CVE-анализ каждой встроенной native-библиотеки.
Публикация и установка нового релиза — отдельный этап.
