# Привязка треков к музыкальным каталогам

Доступно с Mumpa 1.3.5 на Windows и Android.

В меню трека открой **Привязка к каталогу**, сравни исполнителя, альбом,
длительность и версию, затем нажми значок ссылки у подходящей записи.
Здесь же можно удалить привязку. После удаления этот трек не привязывается
автоматически, пока пользователь снова не выберет запись вручную.

Для доступного локально трека приложение также пробует автоматическое
сопоставление после 15 секунд воспроизведения. В настройках метаданных его
можно отключить. Поиск отправляет название и исполнителя в MusicBrainz и
Deezer; аудио, пути файлов, ссылки раздач и учётные данные туда не передаются.
Массового сканирования библиотеки нет. Для торрент-файлов нужны прочитанные
теги: сведения из названия раздачи сами по себе не подтверждают запись.

## Что сохраняется и где используется

- В `library.json` сохраняются идентификаторы записи и всех исполнителей
  с указанием каталога (`musicbrainz:…`, `deezer:…`), ISRC, метаданные,
  дата, способ выбора и признаки совпадения.
- Очистка сетевого кеша не удаляет привязки. Они входят в экспорт профиля;
  переимпорт неизменившегося файла сохраняет их. Исходные теги не переписываются.
- Поиск в библиотеке учитывает каталожное название и псевдонимы исполнителей.
  Переход на страницу исполнителя использует точный ID, если он известен.
- Подтверждённые ID участвуют в группировке копий: одинаковые текстовые
  названия больше не объединяют две разные подтверждённые записи.
- Радио использует сохранённый MusicBrainz ID для уже существующего источника
  похожих исполнителей ListenBrainz. Deezer здесь является каталогом метаданных;
  персональные рекомендации Deezer и потоковое аудио не подключены.

Смена названия, исполнителя, альбома или существенное изменение длительности
сбрасывают старую привязку. Поздний ответ API не восстанавливает удалённый трек
и не перезаписывает ручной выбор или отключение автоматического сопоставления.

## Правила сопоставления

Автоматический выбор требует согласия названия, исполнителя, альбома и
длительности (допуск 2–4 секунды), отсутствия различий в версии и единственного
лидера среди кандидатов. Регистр, пунктуация и `ё/е` нормализуются. Транслитерация
принимается только при наличии каталожного псевдонима. Для `feat.` проверяются
все указанные участники. Live, acoustic, remix, radio edit, remaster и другие
существенные пометки не удаляются при сравнении.

Записи разных каталогов объединяются по ISRC только при согласии исполнителя,
названия, длительности и версии. Совпадение одних строк не создаёт межкаталожную
связь. Несколько почти одинаковых записей без общей идентичности остаются
для ручного выбора. В поиске файлов исполнитель берётся из найденной раздачи
или папки, а не подставляется из запроса.

API запрашиваются независимо, с тайм-аутами, отменой, ограниченным размером
ответов, очередями и кешем. При отказе одного каталога остаются результаты
второго, а интерфейс сообщает о неполном ответе. Ошибки Deezer, включая JSON
с `error` при HTTP 200, не кешируются как пустой каталог.

## Проверка 17 ноября 2026

Публичный набор: 16 заранее выбранных песен, из них 12 русскоязычных.
Исполнитель и название выбраны вручную; альбом и длительность проверены по
каталогу. Это проверка согласованности метаданных, а не распознавание аудио
и не независимая оценка точности на случайной выборке.

| Проверка | Результат |
|---|---|
| Сохранённые ответы Deezer, 16 публичных примеров | 14 автоматических совпадений, 2 отказа |
| Контрольные изменения исполнителя, длительности и Live-версии | Все 48 неверных вариантов отклонены |
| Живые MusicBrainz + Deezer, те же 16 песен | 11 автоматических совпадений, включая 7 из 12 русских |
| Ранее сохранённые ответы для 24 реальных локальных треков, без сети | 15 автоматических совпадений, 9 отказов |

В живом прогоне автоматически сопоставились Кино («Группа крови», «Звезда
по имени Солнце»), Земфира («Искала»), Би-2 («Полковнику никто не пишет»),
Сплин («Выхода нет»), Дайте танк (!) («Люди»), Oxxxymiron («Город под подошвой»),
а также Daft Punk, Nirvana, Queen и Radiohead из тестового набора.

ДДТ, Король и Шут и Noize MC остались на ручной выбор из-за равнозначных записей
без достаточных общих ID. Для Мумий Тролль не совпал весь набор подтверждений
альбома/псевдонима. Для Касты кандидатов в том прогоне не было. MusicBrainz
оказался временно недоступен для четырёх запросов; Deezer позволил обработать
три из них. Состояние внешних каталогов и набор кандидатов меняются.

Отдельный живой запрос «Ежемесячные feat. Блёв Мс — Роженица в метро» сохранил
обоих участников и объединил запись MusicBrainz
`b6867a43-3919-40e8-aba8-646d744f55bc` с Deezer `3230194751`
по ISRC `FR2X42545138`.

Воспроизводимые публичные ответы: `test/fixtures/catalog-deezer-20261117.json`.
Обычный `flutter test` не обращается к этим внешним API. Опциональные живые проверки:

```powershell
flutter test test/catalog_quality_test.dart --dart-define=CATALOG_LIVE_TEST=true
flutter test test/catalog_quality_test.dart --dart-define=CATALOG_PUBLIC_LIVE_BATCH=true
```

Личные примеры и локальные отчёты находятся только в игнорируемом `test-output`.
Пользовательская библиотека при оценке не изменялась. Оценка по метаданным
не доказывает идентичность звука: акустический fingerprint здесь не реализован.
