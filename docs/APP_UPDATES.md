# Установка Windows и обновления Mumpa

Начиная с 1.2.14 Windows ZIP содержит `Mumpa/Install Mumpa.cmd`.
Распакуй архив целиком и запусти этот файл. Установка не требует прав
администратора: программа находится в `%LOCALAPPDATA%\Programs\Mumpa\current`,
ярлык **Mumpa** — в пользовательском меню «Пуск», запись — в списке
установленных приложений. Запуск `mumpa.exe` из ZIP остаётся переносным.

## Обновление из приложения

**Настройки → О приложении → Проверить обновления → Скачать обновление**.
При запуске проверка выполняется автоматически, если переключатель включён.
Загрузка и установка выполняются по кнопке. Показываются объём и прогресс;
загрузку можно отменить и повторить.

Windows: **Установить и перезапустить**. Установщик распаковывает и проверяет
новую программу, затем Mumpa сохраняет библиотеку и завершает воспроизведение.
После выхода процесса файлы заменяются и программа запускается снова.
Предыдущая программа сохраняется в `previous`, при ошибке замены возвращается
автоматически. Установщик не завершает процесс принудительно. Нельзя обновить
второй запущенный экземпляр, который держит файлы установленной программы.
Установка из переносного запуска создаёт ту же постоянную установку.

С **1.2.29** установщик запускается с `CREATE_BREAKAWAY_FROM_JOB`: обычный
`Start-Process` наследовал Windows job Mumpa и завершался вместе с приложением
после статуса `ready`. Native runner разрешает явный breakaway; обычные
дочерние службы по-прежнему завершаются при выходе. Ошибка запуска независимого
установщика показывается до закрытия Mumpa.

Версиям до 1.2.29 требуется однократная внешняя установка исправленной
Windows-сборки через `Install Mumpa.cmd` после полного выхода через трей.
Повторное скачивание архива не исправляет код работающей старой версии.

С **1.2.27** скрипты, извлечённые из ресурсов приложения, записываются в UTF-8
с BOM: загрузчик ресурсов Dart снимает BOM исходного файла, а Windows
PowerShell 5.1 иначе читает кириллицу как системную ANSI-кодировку. Это
устраняет ошибку старых Windows-сборок «Установщик не ответил», возникавшую
до начала установки. [Поведение кодировок Windows PowerShell](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_character_encoding).

Обычный дочерний PowerShell запускает отдельный скрытый процесс установщика
через `Start-Process` и завершается после передачи PID. Это обходит
неработающий на проверенном ПК `ProcessStartMode.detached`. Параметры
передаются через JSON и `EncodedCommand`, включая пути с кириллицей,
пробелами и апострофами. Приложение читает однострочное подтверждение запуска,
не дожидаясь закрытия унаследованных фоновым процессом каналов вывода.

Отдельный ASCII-launcher пишет первый статус сразу после запуска, сохраняет
вывод и ошибки в `%USERPROFILE%/.mumpa/updates/install.log` и сообщает также
об ошибках разбора основного скрипта. Если сам launcher не отвечает,
приложение сообщает об этом через 15 секунд. Распаковка и проверка пакета
по-прежнему проходят перед завершением работающего приложения. Старой
версии с уже сломанным запуском helper требуется однократное внешнее
обновление; повторное скачивание того же ZIP не исправляет этот запуск.

Начиная с 1.2.21 музыка, плейлисты, любимое и настройки находятся в едином
`%USERPROFILE%\.mumpa`. Старые ApplicationSupport/AppData-профили, включая
копии внутри MSIX-хостов, объединяются однократно без удаления оригиналов.
Профиль общий для запуска из «Пуска», Explorer, Codex и pi; два экземпляра
не могут одновременно его перезаписывать. Подробнее: [WINDOWS_PROFILE.md](WINDOWS_PROFILE.md).
Удаление через список приложений сохраняет эти данные.

Android: скачивается APK для поддерживаемого ABI. **Установить обновление**
передаёт файл системному установщику через FileProvider с доступом только
к папке обновлений. Android 8+ может попросить разрешить установку из Mumpa.
После выдачи разрешения надо вернуться и повторить кнопку установки.
Подпись новой версии должна совпадать с установленной. CI с временным debug
ключом не гарантирует совместимые обновления: нужен постоянный release key,
как описано в [CI.md](CI.md).

## Публичный и приватный репозиторий

Первый запрос всегда идёт по публичной ссылке
`https://github.com/d0rj/mumpa/releases/latest/download/BUILD.json`.
Из неё читается полный `version+build`; `SHA256.json` и пакет запрашиваются
по **конкретному тегу** `v<version>`, чтобы новый релиз во время загрузки
не смешал версии. В памяти не держится весь ZIP: пакет пишется на диск потоком.
Фактические размер и SHA-256 должны совпасть с манифестом. Перед установкой
они проверяются ещё раз. Недокачанный `.part` не является обновлением.

Пока репозиторий приватный, Windows после неудачного публичного запроса
обращается к GitHub CLI (`gh api`) с авторизацией текущего пользователя.
Mumpa не читает, не копирует и не сохраняет токен. Для другого компьютера
нужны GitHub CLI, `gh auth login` и доступ к репозиторию. Android не использует
этот локальный Windows способ авторизации.

После перевода репозитория в **Public** следующий запрос использует обычные
публичные файлы. GitHub CLI и токен больше не нужны, в том числе на Android.
Способ авторизации не сохраняется между проверками. Это проверено отдельным
тестом: приватная проверка → публичная проверка → скачивание без вызова CLI.
Достаточно менять видимость репозитория; URL и код обновлятора менять не надо.

Обновление предлагается только для более новой стабильной версии. Нужен
опубликованный **GitHub Release** с `BUILD.json`, `SHA256.json` и пакетом
устройства; одного commit, git tag или Actions Artifact недостаточно.
Их уже создаёт workflow Build release. Draft и prerelease не устанавливаются.
Ошибки сети/доступа показываются в разделе обновлений и не мешают приложению.

## Проверки

- `flutter test --no-pub --no-test-assets`: версии, повреждённые/обрезанные
  пакеты, повтор после ошибки, ограничения метаданных, публичный переход,
  изменение файла перед установкой и интерфейс на узком/широком экране.
- `tools/test-install-windows.ps1`: настоящая файловая установка, обновление,
  предыдущая версия, принудительная ошибка после замены и откат, ZIP traversal,
  неверная контрольная сумма, равенство helper в инструментах и assets.
- `test/windows_update_installer_test.dart`: BOM после декодирования ресурсов,
  реальный Windows PowerShell 5.1, ошибка парсера в дочернем скрипте, ограниченный
  запуск и полная передача управления с ожиданием старого процесса,
  заменой файлов и сохранением предыдущей версии в изолированной установке.
- Опциональная сетевая проверка на Windows:
  `flutter drive -d windows --driver integration_test/driver.dart --target integration_test/app_update_test.dart --dart-define=APP_UPDATE_TEST=true`.
  Она проверяет настоящий релиз и native версию. Для полного скачивания ZIP
  добавь `--dart-define=APP_UPDATE_DOWNLOAD_TEST=true`. Отчёт сохраняется
  в `test-output/native-app-update-1.2.14.json`; `packageVerified` явно отличает
  проверку сведений от полного скачивания. Пользовательская библиотека и
  установленная версия в этом тесте не заменяются.
- Проверка доступа к настоящим приватным метаданным без отдельного окна:
  `flutter test --no-pub --no-test-assets test/app_update_live_test.dart --dart-define=APP_UPDATE_LIVE_TEST=true`.

Источники протокола: [GitHub Releases API](https://docs.github.com/en/rest/releases/releases),
[FileProvider](https://developer.android.com/reference/androidx/core/content/FileProvider),
[Android install permission](https://developer.android.com/reference/android/provider/Settings#ACTION_MANAGE_UNKNOWN_APP_SOURCES).
