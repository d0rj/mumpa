# Первый запуск и личные данные — 1.2.25

Новая установка Windows/Android использует «Автоматически»: ленту
[Knaben API v1](https://knaben.org/api/v1/) и объединённый поиск Knaben +
[RuTor](https://rutor.info/). Прямой RuTor запрашивает только музыкальную
категорию, отсекает видеоконцерты и отдаёт magnet либо torrent-файл.
Не нужны свой сервер, ключ, аккаунт или Chromium. Лента, поиск альбомов,
поиск версий записи MusicBrainz и радио используют выбранный источник.
Для magnet в автоматическом режиме Mumpa сначала пробует получить torrent-файл
из публичного кеша [Torrage](https://torrage.info/), затем при необходимости
получает метаданные у пиров. Ожидание ограничено таймаутом и отменяется при
новом выборе. Метаданные торрента не доказывают наличие аудиобайтов у доступных пиров.

Категории Knaben ограничены MP3 (1001000) и lossless (1002000), без аудиокниг и
видеофайлов. Ответ дополнительно фильтруется локально; пригодны только
magnet с корректным BTIH. Одинаковые хеши объединяются. Запросы не содержат
ключ пользовательского Jackett. Встроенные помощники не запускаются в
автоматическом режиме, даже если ранее были включены.

С 1.2.25 явный музыкальный запрос Knaben возвращает до 300 результатов без
общего фильтра возраста/риска каталога. Прежняя проверка `virusDetection: 0`
оставляла один альбом, скрывая полную дискографию «Ежемесячных». Фильтры
музыкальных категорий, формата ссылок и дубликатов сохраняются. Стартовая лента
по-прежнему использует более строгий фильтр. Показатель каталога не является
антивирусной проверкой, а наличие аудиорасширения не гарантирует безопасность
декодера. Mumpa импортирует только поддерживаемые аудиофайлы и не запускает
исполняемые файлы из раздач.

Кешу метаданных передаётся только публичный infohash, без названия из magnet,
tracker URL, passkey, cookies или ключей Jackett. Читается параметр обычной
публичной ссылки скачивания; JavaScript страницы не выполняется, перенаправления
скачивания разрешены только на HTTPS-узлы Torrage и ограничены тремя переходами.
Перед записью проверяются bencode, ограничения
размера/путей, точное совпадение infohash и наличие аудиофайлов. Неподходящий
ответ не попадает в библиотеку; недоступность кеша оставляет обычный magnet.
Это устраняет зависимость списка альбомов от ответа пиров, но не заменяет их
при скачивании самой музыки.
При объединении сохраняются исходные байты `info`, а адреса трекеров из выбранного
magnet добавляются к старым адресам кеша. В частности, параметр `?magnet` не
теряется. Новые адреса остаются только локально и не отправляются в кеш.

Источники запрашиваются параллельно, одинаковые infohash объединяются.
При наличии прямого torrent-файла он имеет приоритет над ожиданием magnet-
метаданных у пиров. Ошибка одного источника не скрывает результаты другого.
Если ничего не найдено и один каталог недоступен, приложение сообщает об этом,
вместо утверждения, что музыки нет. Для Android нужны только APK и сеть;
отдельного сервера или приложения Jackett этот режим не использует.

VPN должен пропускать соединения с трекерами и раздающими. В сравнении от
2026-10-18 одна и та же полная дискография отдала целый MP3 через ранее выбранный
Windows Wi-Fi, но не передала данные через системный маршрут VPN ни на Windows,
ни на Android-эмуляторе. Одинаковая Wi-Fi сеть не означает одинаковый маршрут
торрент-трафика. На физическом планшете пользователя этот вывод ещё нужно
проверить: пользователь использует Durev VPN в автоматическом режиме с поддержкой
торрентов; этот VPN в эмуляторе не проверялся. В повторном прямом Wi-Fi тесте
раздача также не всегда успевала передать данные. Нельзя считать наличие VPN
доказанной причиной проблемы на планшете. Если отдельная проверка подтвердит,
что VPN блокирует такие соединения, можно явно исключить Mumpa из
VPN в настройках самого VPN либо использовать совместимый VPN. Приложение не
отключает VPN и не выбирает обходящий его интерфейс автоматически. На Windows
сохраняется явный выбор сети в настройках Mumpa.

При обновлении сохраняется прежний выбранный источник. «Автоматически»
в настройках поиска переключает его без удаления собственного URL/API key.
Запоздалый ответ прежнего источника не заменяет новую ленту. Свой Jackett
настраивается в раскрываемом дополнительном разделе. Прямой вход в RuTracker
сам выбирает прямой источник и оставляет пароль/cookies в браузерном профиле.
Это доступный путь при `Empty cookies returned by FlareSolverr`; ошибки
самого стороннего Jackett/FlareSolverr Mumpa не скрывает.

## Хранение и восстановление

Рабочий профиль Windows находится в `%USERPROFILE%/.mumpa`, отдельно от
установки и checkout. Старые AppData-профили объединяются однократно с
сохранением оригиналов и проверкой скопированных файлов. Единый путь не
зависит от запуска из Codex, pi или Explorer; межпроцессная блокировка
предотвращает конкурирующую запись. Подробнее: [WINDOWS_PROFILE.md](WINDOWS_PROFILE.md).
`library.json` содержит избранное, плейлисты, метаданные и настройки.
Обновление бинарников и очистка кеша не создают новый профиль.

Перед загрузкой проверяется весь снимок, включая типы настроек и ссылок
избранного. Порядок восстановления: основной JSON, незавершённый атомарный
снимок `.tmp`, `.bak`, затем дневные копии от новых к старым. Сохраняются
последние 7 дней, в которые библиотека записывалась; копия текущего дня
содержит последний успешный снимок. Это локальные копии, они не защищают от
удаления всей папки данных или поломки диска. Копии включают настройки
подключений: не публиковать их в отчётах и репозитории.

При восстановлении повреждённый основной файл сохраняется отдельно, а
здоровая резервная копия не заменяется повреждённым JSON. Если все поколения
нечитаемы, приложение сохраняет исходные файлы и блокирует запись вместо
перезаписи пустой библиотекой. Предупреждение видно в приложении.

Очистка проекта сначала проверяет весь план и отказывается удалять дерево
с библиотекой или профилем Jackett, даже внутри `.local`/build. Тесты удаляют
свои синтетические профили сами. Исходники и полная последняя сборка
сохраняются по общим правилам упаковки.

## Проверки

- `test/public_music_catalog_test.dart`: запрос без ключа, UTF-8, категории,
  некорректные ссылки, дубликаты, отмена и ограничения API.
- `test/magnet_metainfo_cache_test.dart`: проверка hash, допустимого содержимого,
  повторное использование кеша, минимизация отправляемых данных, ошибки и таймаут.
- `test/automatic_sources_test.dart`: первый запуск без помощников,
  сохранение собственных настроек и запоздалый ответ старого источника.
- `test/profile_recovery_test.dart`: независимые резервные копии, повторный
  сбой, запрет перезаписи повреждённых данных. Opt-in `MUMPA_PROFILE_AUDIT`
  проверяет изолированную копию существующего профиля.
- `integration_test/first_run_test.dart` с
  `--dart-define=FIRST_RUN_NETWORK_TEST=true`: живой каталог и поиск с
  кириллицей в Windows, загрузка копии пользовательских любимых треков,
  настоящее воспроизведение сохранённого трека. Исходный профиль не меняется.
