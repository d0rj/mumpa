# Mumpa

Музыкальное приложение для **Windows x64 и Android 7.0+**, написанное на Flutter. Локальные альбомы, torrent-стриминг и полные офлайн-копии объединены в одной медиатеке. Интерфейс: тёмная тема, обложки, боковая навигация на ПК, нижняя навигация и раскрывающийся плеер на телефоне.

## Запуск готовой версии

- **Windows:** распаковать `artifacts/Mumpa-1.1.3-windows-x64.zip` и запустить `Mumpa/mumpa.exe`. Вся папка нужна для работы. Если Windows запросит сетевой доступ TorrServer при первом torrent-запуске, разрешение относится к встроенному движку. Его путь постоянный; для каждой проверки новая копия больше не создаётся.
- **Android:** установить `artifacts/Mumpa-1.1.3-android-arm64.apk`. Это вариант для большинства современных телефонов. Также собраны ARMv7 и x86_64. APK предназначены для прямой установки, подписаны локальным development-ключом, не опубликованы в магазине.
- Демо больше не добавляется при новой установке. Уже существующий демо-альбом помечен как демо и остаётся в пользовательской медиатеке.

## Музыка

Нажми на раздачу в каталоге или поиске — Mumpa откроет её коллекцию с полным списком аудиотреков и сохранит одноимённый плейлист. Нажатие на любой трек начинает поток с этого трека и ставит коллекцию в очередь. Полная загрузка перед прослушиванием не требуется. Повторное открытие той же раздачи использует существующий плейлист и сохраняет внесённые изменения.

При подключении показываются реальные подключённые пиры и время ожидания. Первые аудиобайты должны поступить за 45 секунд; при отсутствии данных появляется сообщение и кнопка «Повторить», сохраняющая выбранный трек и очередь. Ожидание можно отменить кнопкой плеера или «Отмена». Избранные треки используют тот же путь воспроизведения и автоскачивания, что и альбомы.

Кнопка **«Добавить музыку»** принимает папку с альбомами, отдельные аудиофайлы, magnet/HTTP-ссылку на `.torrent` или сам `.torrent`-файл. Torrent-файл и ссылка также открываются сразу как коллекция. В меню каждого трека есть «Слушать следующим», добавление в очередь, выбранный плейлист или текущий воспроизводимый плейлист; последняя команда добавляет трек и в его текущую очередь. Всю коллекцию можно скачать отдельно кнопкой на её странице.

Форматы: MP3, FLAC, M4A/AAC, OGG/Opus, WAV, AIFF, APE, WMA, ALAC и аудио WebM; декодирование выполняет libmpv. Доступность конкретного кодека зависит от файла и нативной библиотеки. Читаются музыкальные теги, номер диска/трека, обложки и встроенный текст песни. Без тегов используются имя файла и папка. На Windows импорт ссылается на оригиналы; на Android выбранные файлы копируются в приватное хранилище приложения через системный выбор файлов/папок.

Есть альбомы и исполнители, поиск по медиатеке, избранное, история, плейлисты, очередь/«следующим», shuffle/repeat, громкость, перемотка и таймер сна. На Android — фоновое воспроизведение, уведомление/системные медиакнопки и обработка отключения наушников. На ПК: `Space` — пауза, `Ctrl+K` — поиск, `Alt+←/→` — предыдущий/следующий трек.

## Torrent и офлайн

Встроен **TorrServer MatriX.145.2-mumpa1** с исправлением отмены HTTP-потока; отдельная установка сервера не нужна. Отключённый клиент освобождает торрент-читателя, даже если аудиоданные ещё не появились. Локальный HTTP API слушает только `127.0.0.1`. Сетевые пиры нужны для torrent-источников. LPD/Bonjour/DLNA и UPnP отключены для новых конфигураций; TCP/uTP, DHT и PEX сохранены. Движок запускается по требованию, не при обычном проигрывании локального файла. В настройках можно подключить свой внешний TorrServer; исправление отмены включено в поставляемый движок Mumpa.

Во время стриминга используется временный кеш частей. **«Скачивать прослушиваемые треки» включено по умолчанию**: после запуска плеера текущий torrent-трек одновременно сохраняется целиком для офлайн. Если в фоне скачивался другой трек, его `.part` сохраняется, текущий получает приоритет, затем предыдущая загрузка автоматически продолжается через HTTP Range. Загрузчик не блокирует декодер; готовность офлайн-копии отображается отдельно от воспроизведения.

**«Скачать коллекцию»**, **«Скачать альбом»** или меню трека позволяют сохранить музыку без прослушивания. Есть очередь, прогресс и пауза; незавершённый `.part` не считается готовой музыкой. Автосохранение можно отключить в настройках; ранее сохранённое явное отключение сохраняется после обновления. Лимит по умолчанию — 4096 МБ; готовые копии остаются до удаления через меню трека. Сначала плеер проверяет офлайн/локальный файл, затем torrent-источник.

Библиотека сохраняется атомарно с резервной копией. Загруженные `.torrent` сохраняются отдельно для восстановления источника после сброса движка. Папка данных показана в настройках; Windows обычно использует `%APPDATA%/app.mumpa/mumpa/Mumpa`, Android — приватную support-папку. Удаление приложения на Android удаляет его приватные копии.

## Каталог Jackett и RuTracker

**Jackett выбран по умолчанию.** На Windows нажми «Настроить Jackett и RuTracker»: Mumpa извлечёт и запустит закреплённую версию Jackett без установки системной службы. В его окне добавь индексатор **RuTracker.org**, укажи свой аккаунт, сохрани и пройди проверку трекера. Закрой окно настройки — Mumpa проверит подключение и покажет музыкальные раздачи. Поиск ограничен категорией Audio, поддерживаются magnet и torrent-файлы из Jackett. Пароль RuTracker вводится в интерфейсе Jackett, а не в чате.

Существующий Jackett/Prowlarr подключается через адрес и API key в настройках. Для Jackett можно указать базовый адрес — Mumpa построит Torznab URL и проверит caps. На телефоне `localhost` означает сам телефон: нужен доступный сетевой адрес внешнего Jackett. Встроенная Windows-копия по умолчанию слушает только loopback; она не является общедоступным сервером. Её профиль находится в `jackett/`, executable — в постоянном `runtime/Jackett-0.24.2806`. Обновления отключены. Существующий Roaming-профиль Jackett не мигрируется и не удаляется: в этом случае используй внешний адрес.

Переключатель «RuTracker напрямую» открывает каталог музыкальных жанров через системный WebView. Полнотекстовый поиск требует вход в RuTracker. Если сайт показывает Cloudflare/captcha, открой его из Mumpa и пройди проверку самостоятельно. Зеркала выбираются в настройках. Cookies остаются в браузерном профиле, библиотечный JSON не содержит пароль RuTracker. Прямой вход и публичный swarm с пользовательским аккаунтом без самого аккаунта проверить нельзя; каталог разделов проверен на живом сайте.

На Windows для окна настройки и прямого каталога нужен установленный Microsoft Edge WebView2 Runtime. Встроенного коммерческого каталога Spotify и аккаунтов Spotify нет.

Поиск запускается при вводе с небольшой задержкой; новый запрос отменяет предыдущий. RuTracker.RU и RuTracker.org — разные индексаторы: для каталога RuTracker.org нужен именно второй. Mumpa сохраняет русские названия из описания RuTracker, даже если Jackett сокращает кириллицу в заголовке. Для открытия предпочитается HTTP-ссылка на `.torrent`: метаданные доступны без ожидания пиров, а magnet остаётся запасным вариантом. Открытие показывает этапы и допускает отмену; ожидание метаданных magnet ограничено 25 секундами.

При ошибке **«Challenge detected but FlareSolverr is not configured»** на Windows нажми **«Настроить FlareSolverr для Cloudflare»** в настройках Mumpa, затем повтори сохранение индексатора в Jackett. Приложение распакует FlareSolverr 3.5.2 с Chromium, запустит его скрыто и подключит к своему Jackett. Первый запуск может загрузить совместимый ChromeDriver. Помощник слушает loopback и закрывается вместе с приложением; включённая настройка восстанавливается при следующем запуске. Архив помощника увеличивает Windows-дистрибутив примерно на 378 МБ. На Android FlareSolverr в APK не входит: настрой его на компьютере или сервере рядом с внешним Jackett.

Список файлов и количество сидов ещё не гарантируют доступность аудиобайтов: для воспроизведения необходима связь с публичными пирами. Локальные и уже полностью скачанные альбомы работают без них. Проверки реального каталога и границы проверки публичного стриминга приведены в `docs/VALIDATION.md`.

## Сборка из исходников

Проверенная среда: Flutter 3.44.4 stable / Dart 3.12.2, Windows Build Tools с C++/Windows SDK, Android SDK и JDK 21. Версии зависимостей закреплены в `pubspec.lock`.

Для сборки движка из исходников нужен Go с разрешённой загрузкой закреплённых toolchain и Android NDK 28.2.13676358. Точные версии и параметры приведены в `engine-patches/README.md`; готовые проверенные engine assets повторно не собираются.

```powershell
./tools/prepare-engines.ps1
./tools/prepare-jackett.ps1
./tools/prepare-flaresolverr.ps1
flutter pub get
flutter analyze
flutter test
flutter test integration_test/app_test.dart -d windows
flutter test integration_test/app_test.dart -d <android-device-id>
flutter build windows --release
flutter build apk --release --split-per-abi
./tools/package-release.ps1
```

Нативные сборки и integration-запуски выполнять последовательно: Flutter обновляет общие файлы регистрации плагинов. Android-пакет включает только Android-движок соответствующей ABI; Windows-движок и архив Jackett — только Windows assets. Android использует AGP 8.13.2 / Gradle 8.13 для совместимости стабильного WebView-плагина; Kotlin 2.3.20.

Скрипты `prepare-engines.ps1`, `prepare-jackett.ps1` и `prepare-flaresolverr.ps1` проверяют SHA-256 закреплённых бинарников и сохраняют соответствующие исходники/лицензии. Исправленный движок собирается через `tools/build-managed-engine.ps1`; закреплённые исходники, overlay, Go/NDK и хеши описаны в `engine-patches/README.md` и `managed-engine.lock.json`. Соответствующие исходники включены в `artifacts/TorrServer-MatriX.145.2-mumpa1-source.zip`. Бинарники, выходные сборки и локальные журналы не добавляются в Git. Integration-тест создаёт оригинальную WAV, локальный tracker и BitTorrent-сидер, проверяет настоящий движок/декодер, избранное, HTTP Range, перемотку, полную загрузку по SHA-256, перезапуск движка и офлайн при выключенном движке/сидере. Три отмены потока без сидера дополнительно проверяют освобождение серверных читателей. Публичные музыкальные торренты тесту не нужны.

Для уже настроенного пользовательского RuTracker.org есть отдельная проверка `flutter test integration_test/real_source_test.dart -d windows --dart-define=REAL_SOURCE_TEST=true`: реальный поиск, загрузка метаинформации и открытие коллекции. Дополнительный флаг `--dart-define=REAL_PLAYBACK_TEST=true` проверяет доступность публичного swarm. `flutter test integration_test/favorites_test.dart -d windows --dart-define=REAL_FAVORITES_TEST=true` проверяет существующее избранное в отдельной библиотеке: настоящее воспроизведение либо завершение ожидания с доступной кнопкой повтора. Ключи и cookies в отчёт не записываются.
