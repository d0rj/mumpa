# Mumpa

Музыкальное приложение для **Windows x64 и Android 7.0+**, написанное на Flutter. Локальные альбомы, torrent-стриминг и полные офлайн-копии объединены в одной медиатеке. Интерфейс: тёмная тема, обложки, боковая навигация на ПК, нижняя навигация и раскрывающийся плеер на телефоне.

## Запуск готовой версии

- **Windows:** распаковать `artifacts/Mumpa-1.0.0-windows-x64.zip` и запустить `Mumpa/mumpa.exe`. Вся папка нужна для работы. Если Windows запросит сетевой доступ TorrServer при первом torrent-запуске, разрешение относится к встроенному движку. Его путь постоянный; для каждой проверки новая копия больше не создаётся.
- **Android:** установить `artifacts/Mumpa-1.0.0-android-arm64.apk`. Это вариант для большинства современных телефонов. Также собраны ARMv7 и x86_64. APK предназначены для прямой установки, подписаны локальным development-ключом, не опубликованы в магазине.
- Оригинальный демо-альбом Mumpa Sessions позволяет сразу проверить звук. Он синтезируется скриптом `tools/generate-demo.py`.

## Музыка

Кнопка **«Добавить музыку»** принимает папку с альбомами, отдельные аудиофайлы, magnet/HTTP-ссылку на `.torrent` или сам `.torrent`-файл. Перед добавлением torrent-альбома можно выбрать нужные треки и указать название/исполнителя.

Форматы: MP3, FLAC, M4A/AAC, OGG/Opus, WAV, AIFF, APE, WMA, ALAC и аудио WebM; декодирование выполняет libmpv. Доступность конкретного кодека зависит от файла и нативной библиотеки. Читаются музыкальные теги, номер диска/трека, обложки и встроенный текст песни. Без тегов используются имя файла и папка. На Windows импорт ссылается на оригиналы; на Android выбранные файлы копируются в приватное хранилище приложения через системный выбор файлов/папок.

Есть альбомы и исполнители, поиск по медиатеке, избранное, история, плейлисты, очередь/«следующим», shuffle/repeat, громкость, перемотка и таймер сна. На Android — фоновое воспроизведение, уведомление/системные медиакнопки и обработка отключения наушников. На ПК: `Space` — пауза, `Ctrl+K` — поиск, `Alt+←/→` — предыдущий/следующий трек.

## Torrent и офлайн

Встроен **TorrServer MatriX.145.2**; отдельная установка сервера не нужна. Локальный HTTP API слушает только `127.0.0.1`. Сетевые пиры нужны для torrent-источников. LPD/Bonjour/DLNA и UPnP отключены для новых конфигураций; TCP/uTP, DHT и PEX сохранены. Движок запускается по требованию, не при обычном проигрывании локального файла. В настройках можно подключить свой внешний TorrServer.

Во время стриминга используется временный кеш частей. **«Скачать альбом»** или меню трека создаёт отдельную полную копию для офлайн. Загрузки имеют очередь, прогресс, паузу и продолжение HTTP Range; незавершённый `.part` не считается готовой музыкой. Настройка **«Скачивать прослушиваемые треки»** включает автоматическое сохранение torrent-треков. Лимит по умолчанию — 4096 МБ; готовые копии остаются до удаления через меню трека. Сначала плеер проверяет офлайн/локальный файл, затем torrent-источник.

Библиотека сохраняется атомарно с резервной копией. Загруженные `.torrent` сохраняются отдельно для восстановления источника после сброса движка. Папка данных показана в настройках; Windows обычно использует `%APPDATA%/app.mumpa/mumpa/Mumpa`, Android — приватную support-папку. Удаление приложения на Android удаляет его приватные копии.

Поиск новых релизов подключается через **свой Torznab API** (например, Jackett/Prowlarr): URL и ключ в настройках, затем поиск в источниках. На телефоне `localhost` означает сам телефон; для сервера на ПК нужен его LAN-адрес. Встроенного каталога Spotify, аккаунтов Spotify и предустановленного музыкального трекера нет.

## Сборка из исходников

Проверенная среда: Flutter 3.44.4 stable / Dart 3.12.2, Windows Build Tools с C++/Windows SDK, Android SDK и JDK 21. Версии зависимостей закреплены в `pubspec.lock`.

```powershell
./tools/prepare-engines.ps1
flutter pub get
flutter analyze
flutter test
flutter test integration_test/app_test.dart -d windows
flutter test integration_test/app_test.dart -d <android-device-id>
flutter build windows --release
flutter build apk --release --split-per-abi
./tools/package-release.ps1
```

Нативные сборки и integration-запуски выполнять последовательно: Flutter обновляет общие файлы регистрации плагинов. Android-пакет включает только Android-движок соответствующей ABI; Windows-движок — только Windows asset.

`prepare-engines.ps1` проверяет SHA-256 каждого закреплённого бинарника. Бинарники, выходные сборки и локальные журналы не добавляются в Git. Integration-тест создаёт оригинальную WAV, локальный tracker и BitTorrent-сидер, проверяет настоящий движок/декодер, HTTP Range, перемотку, полную загрузку по SHA-256, перезапуск движка и офлайн при выключенном движке/сидере. Публичные музыкальные торренты тесту не нужны.
